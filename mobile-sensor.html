🛟 为什么必须做降级？

① 桌面浏览器 / 模拟器 / 无加速度芯片的设备根本不会带有效数据的 devicemotion 事件，页面若只认传感器就会永远"死"在那里——降级按钮让核心功能（抽菜谱）在任何设备都可用；
② Chrome 桌面端会触发 devicemotion 但 accelerationIncludingGravity 全为 null，必须判空而不是报错；
③ iOS 13+ 出于隐私要求传感器 API 必须由用户手势触发 requestPermission()，拒绝授权后同样要落到降级方案；
④ 传感器 API 还要求安全上下文（HTTPS 或 localhost），用 http / file:// 打开时 iOS 会直接拒绝授权——降级是唯一兜底；
⑤ 微信内置浏览器（iOS）经常拦截传感器授权，需提示用户改用 Safari 打开。

⚖️ accelerationIncludingGravity vs acceleration

accelerationIncludingGravity：设备感受到的总加速度 = 用户运动加速度 + 重力分量。手机静置平放时它 ≈ {x:0, y:0, z:9.8}——z 轴那 9.8 就是重力；摇一摇看它，是因为重力基准让"晃动"信号更强、也更省一次滤波。
acceleration：系统扣掉重力后的线性加速度（陀螺仪/重力滤波补偿）。静置时 ≈ {0,0,0}，只反映真实的移动运动。
一句话：前者"含重力的原始读数"，后者"去重力后的净加速度"；本页用前者 + 阈值 18（静置 ≈9.8，晃动瞬时可达 20+，阈值好定）。
