事件侦探：一次拖动到底发生了什么

用手机（或 DevTools 设备模式）在 第 3 节探针区 做五种操作，本页会自动把事件顺序、坐标、次数记下来——下面第 4 节的记录表就是依据这些日志整理的。

1五种操作

① 单击② 向上拖动③ 向左快速滑④ 双指触摸（可选）⑤ 长按后抬起

3探针区（第 3 节）

手指按住区域随意操作。日志记录 touchstart / touchmove / touchend / touchcancel / click 的顺序与坐标；每次手势结束自动插入一条 ■ 统计。canvas 同步画出手指轨迹（加分项 · 数字版轨迹草图）。

在此区域内 单击 / 拖动 / 快滑 / 双指 / 长按touch-action:none · 事件全部留在本区域

4实验记录表（5 种操作的事件顺序）

操作实测事件顺序备注
单击touchstart → touchend → click没有 touchmove；click 由浏览器在 touchend 后合成
向上拖动touchstart → touchmove×N → touchend位移大不补发 click；N 随距离增大
向左快速滑touchstart → touchmove×少量 → touchend快滑时长短，move 次数反而比慢拖少
双指触摸touchstart(1指) → touchstart(2指) → touchmove×N → touchend(剩1指) → touchend(0指)每根手指各自触发 start/end
长按后抬起touchstart → touchend → click静置不动抬起，Chrome 仍补发 click；若长按弹系统菜单/被接管则收到 touchcancel

5三个验收问题

① 一次拖动里 touchmove 大约触发多少次、和距离有什么关系？

touchmove 按屏幕刷新率节流：60Hz 约 每 16~17ms 一次，所以次数 ≈ 拖动时长 × 60。距离越长 → 时长越长 → 次数越多（与距离正相关，但本质跟时间走）。一次 10cm 左右的慢拖大约几十到一百多次；探针区每次手势结束的"■ 统计"给出了实测值。

② click 出现在 touchend 之前还是之后？

之后。浏览器要等 touchend 判定"这不算拖动"（位移小于阈值）才合成 click，顺序永远是 touchstart → touchend → click。单击和静置长按都会看到这条链；大位移拖动不会。

③ 如果把 touchend 换成 touchcancel，会发生什么？

正常手势的收尾逻辑永远不执行。touchcancel 只在系统打断时触发：来电、系统弹窗、浏览器接管手势（长按菜单、边缘滑动手势）等——正常抬起只来 touchend。所以只监听 cancel，单击、拖动都不会被"结账"，状态机会卡死。正确做法是两个都监听：end 按正常结束处理，cancel 按"中断"处理并复位。点上面"模拟一次系统打断"按钮可以在日志里看到 cancel 长什么样。
